# Attestation and metadata statement

!!! warning

    Disclaimer: you **should not** ask for the Attestation Statement unless you are working on an application that requires a high level of trust (e.g. Banking/Financial Company, Government Agency...).

With Symfony, you must enable this feature and define a Metadata Statement Repository in the configuration file.

```yaml title="config/packages/webauthn.yaml" linenums="1"
webauthn:
    metadata:
        enabled: true
        mds_repository: 'App\Repository\MyMetadataStatementRepository'
        status_report_repository: 'App\Repository\MyStatusReportRepository'
```

!!! warning

    The MDS and Status Report repositories shall implement `Webauthn\MetadataService\MetadataStatementRepository`  and `Webauthn\MetadataService\StatusReportRepository`  respectively

!!! danger

    If the metadata service is not enabled, the Attestation Statement Formats other than `None` (e.g. `Apple`, `Packed`, `TPM`...) **cannot be used**.

!!! warning

    **New in v5.3.12:** some TPMs sign their attestation statement with `RS1` (RSASSA-PKCS1-v1\_5 with SHA-1), which is no longer acceptable for digital signatures. Verifying such a statement emits an `E_USER_WARNING`, which the Symfony error handler turns into an exception in the dev environment, and which `web-auth/cose-lib` v5.0.0 will replace with an exception. Declaring the `webauthn.cose.algorithm.RS1` service changes nothing here: the TPM attestation statement support does not use the algorithm manager.

If your application has to keep registering these authenticators, for instance to pass the platform attestation tests of the FIDO Conformance Tools, acknowledge the algorithm. The option is `false` by default.

```yaml title="config/packages/webauthn.yaml" linenums="1"
webauthn:
    metadata:
        enabled: true
        mds_repository: 'App\Repository\MyMetadataStatementRepository'
        status_report_repository: 'App\Repository\MyStatusReportRepository'
        tpm_acknowledge_insecure_algorithm: true
```

### Credential creation options

By default, no Attestation Statement is asked to the Authenticators (type = `none`). To change this behavior, you just have to set the corresponding parameter in the `Webauthn\PublicKeyCredentialCreationOptions` object.

There are 3 conveyance modes available using PHP constants provided by the class `Webauthn\PublicKeyCredentialCreationOptions`:

* `ATTESTATION_CONVEYANCE_PREFERENCE_NONE`: the Relying Party is not interested in authenticator attestation (default)
* `ATTESTATION_CONVEYANCE_PREFERENCE_INDIRECT`: the Relying Party prefers an attestation conveyance yielding verifiable attestation statements, but allows the client to decide how to obtain such attestation statements.
* `ATTESTATION_CONVEYANCE_PREFERENCE_DIRECT`: the Relying Party wants to receive the attestation statement as generated by the authenticator.
* `ATTESTATION_CONVEYANCE_PREFERENCE_ENTERPRISE`: the Relying Party wants to receive uniquely identifying information from authenticators.

```yaml title="config/packages/webauthn.yaml"
webauthn:
    credential_repository: ...
    user_repository: ...
    creation_profiles:
        acme:
            attestation_conveyance: !php/const Webauthn\PublicKeyCredentialCreationOptions::ATTESTATION_CONVEYANCE_PREFERENCE_DIRECT
            rp:
                name: 'My application'
                id: 'example.com'
```
