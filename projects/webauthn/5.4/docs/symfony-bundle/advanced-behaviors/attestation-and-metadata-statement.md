# Attestation and metadata statement

!!! warning

    Disclaimer: you **should not** ask for the Attestation Statement unless you are working on an application that requires a high level of trust (e.g. Banking/Financial Company, Government Agency...).

With Symfony, you must enable this feature and define a Metadata Statement Repository in the configuration file.

```yaml title="config/packages/webauthn.yaml" linenums="1"
webauthn:
    metadata:
        enabled: true
        mds_repository: 'App\Repository\MyMetadataStatementRepository'
        status_report_repository: 'App\Repository\MyStatusReportRepository'
```

!!! warning

    The MDS and Status Report repositories shall implement `Webauthn\MetadataService\MetadataStatementRepository`  and `Webauthn\MetadataService\StatusReportRepository`  respectively

!!! danger

    If the metadata service is not enabled, the Attestation Statement Formats other than `None` (e.g. `Apple`, `Packed`, `TPM`...) **cannot be used**.

!!! danger

    **Changed in v5.3.13:** with the metadata support enabled and an attestation requested, two kinds of authenticators that used to be registered are now refused.

    * An authenticator model is refused as soon as any of its status reports is a security notification or `REVOKED`, wherever the report sits in the list ([GHSA-p8cj-mmjr-5c2m](https://github.com/web-auth/webauthn-framework/security/advisories/GHSA-p8cj-mmjr-5c2m)). See [Status report repository](../../pure-php/advanced-behaviours/attestation-and-metadata-statement.md#status-report-repository).
    * A full attestation (basic, AttCA, AnonCA) under the null AAGUID, which FIDO U2F security keys and Apple anonymous attestations report, is verified like any other: the Metadata Statement Repository must return a statement for `00000000-0000-0000-0000-000000000000` whose attestation root certificates include their roots ([GHSA-2jv3-c2vg-rhc4](https://github.com/web-auth/webauthn-framework/security/advisories/GHSA-2jv3-c2vg-rhc4)). See [Metadata statement repository](../../pure-php/advanced-behaviours/attestation-and-metadata-statement.md#metadata-statement-repository).

    Since v5.4.0, a listener can admit a flagged model, and `require_statement: false` accepts, unverified, the attestations whose AAGUID has no statement, the null AAGUID included. See [Admitting a compromised authenticator](#admitting-a-compromised-authenticator) and [Authenticators without a metadata statement](#authenticators-without-a-metadata-statement).

!!! warning

    **New in v5.3.12:** some TPMs sign their attestation statement with `RS1` (RSASSA-PKCS1-v1\_5 with SHA-1), which is no longer acceptable for digital signatures. Verifying such a statement emits an `E_USER_WARNING`, which the Symfony error handler turns into an exception in the dev environment, and which `web-auth/cose-lib` v5.0.0 will replace with an exception. Declaring the `webauthn.cose.algorithm.RS1` service changes nothing here: the TPM attestation statement support does not use the algorithm manager.

If your application has to keep registering these authenticators, for instance to pass the platform attestation tests of the FIDO Conformance Tools, acknowledge the algorithm. The option is `false` by default.

```yaml title="config/packages/webauthn.yaml" linenums="1"
webauthn:
    metadata:
        enabled: true
        mds_repository: 'App\Repository\MyMetadataStatementRepository'
        status_report_repository: 'App\Repository\MyStatusReportRepository'
        tpm_acknowledge_insecure_algorithm: true
```

## Credential creation options

By default, no Attestation Statement is asked to the Authenticators (type = `none`). To change this behavior, you just have to set the corresponding parameter in the `Webauthn\PublicKeyCredentialCreationOptions` object.

There are 4 conveyance modes available using PHP constants provided by the class `Webauthn\PublicKeyCredentialCreationOptions`:

* `ATTESTATION_CONVEYANCE_PREFERENCE_NONE`: the Relying Party is not interested in authenticator attestation (default)
* `ATTESTATION_CONVEYANCE_PREFERENCE_INDIRECT`: the Relying Party prefers an attestation conveyance yielding verifiable attestation statements, but allows the client to decide how to obtain such attestation statements.
* `ATTESTATION_CONVEYANCE_PREFERENCE_DIRECT`: the Relying Party wants to receive the attestation statement as generated by the authenticator.
* `ATTESTATION_CONVEYANCE_PREFERENCE_ENTERPRISE`: the Relying Party wants to receive uniquely identifying information from authenticators. See [Enterprise attestation](#enterprise-attestation).

Set the preference on the [options helper](../options-helpers.md) of your registration endpoint:

```php linenums="1"
use Webauthn\PublicKeyCredentialCreationOptions;

return $this->options
    ->forCreation('example.com', $this->userEntityGuesser)
    ->withAttestation(PublicKeyCredentialCreationOptions::ATTESTATION_CONVEYANCE_PREFERENCE_DIRECT)
    ->build($request);
```

!!! warning

    **Deprecated in v5.4.0:** the creation profiles, and their `attestation_conveyance` node, are superseded by the options helpers and removed in 6.0.0. See [From 5.3 to 5.4](../../migration/from-v5.3-to-v5.4.md).

```yaml title="config/packages/webauthn.yaml"
webauthn:
    credential_repository: ...
    user_repository: ...
    creation_profiles:
        acme:
            attestation_conveyance: !php/const Webauthn\PublicKeyCredentialCreationOptions::ATTESTATION_CONVEYANCE_PREFERENCE_DIRECT
            rp:
                id: 'example.com'
```

## Authenticators without a metadata statement

!!! info

    **New in v5.4.0**

A full attestation (basic, AttCA or AnonCA) whose AAGUID has no Metadata Statement is refused by default. Set `require_statement` to `false` to accept it without its certificate chain being verified. The status reports of the AAGUID still apply, and the AAGUIDs that have a statement are verified as before.

```yaml title="config/packages/webauthn.yaml" linenums="1"
webauthn:
    metadata:
        enabled: true
        mds_repository: 'App\Repository\MyMetadataStatementRepository'
        status_report_repository: 'App\Repository\MyStatusReportRepository'
        require_statement: false
```

The `Webauthn\Event\AttestationCheckedAgainstMetadata` event tells whether the model was verified against its statement or only declared by the authenticator:

```php linenums="1"
<?php

declare(strict_types=1);

namespace App\EventListener;

use Symfony\Component\EventDispatcher\Attribute\AsEventListener;
use Webauthn\Event\AttestationCheckedAgainstMetadata;

#[AsEventListener(AttestationCheckedAgainstMetadata::class)]
final readonly class RecordAuthenticatorModel
{
    public function __construct(
        private AuthenticatorModelRepository $authenticatorModels,
    ) {
    }

    public function __invoke(AttestationCheckedAgainstMetadata $event): void
    {
        $this->authenticatorModels->record(
            $event->credentialRecord->publicKeyCredentialId,
            $event->credentialRecord->aaguid->toRfc4122(),
            $event->isVerified()
        );
    }
}
```

See [Authenticators without a metadata statement](../../pure-php/advanced-behaviours/attestation-and-metadata-statement.md#authenticators-without-a-metadata-statement) for the details and the limits of an unverified attestation.

## Admitting a compromised authenticator

!!! info

    **New in v5.4.0**

Before refusing a model flagged by a status report, the bundle dispatches `Webauthn\Event\CompromisedAuthenticatorDetected`. The registration goes on only when a listener calls `admit()`:

```php linenums="1"
<?php

declare(strict_types=1);

namespace App\EventListener;

use DateTimeImmutable;
use Psr\Clock\ClockInterface;
use Symfony\Component\DependencyInjection\Attribute\Autowire;
use Symfony\Component\EventDispatcher\Attribute\AsEventListener;
use Webauthn\Event\CompromisedAuthenticatorDetected;

#[AsEventListener(CompromisedAuthenticatorDetected::class)]
final readonly class AdmitFleetUntilReplacement
{
    public function __construct(
        private ClockInterface $clock,
        #[Autowire('%app.webauthn.fleet_model%')]
        private string $fleetModel,
        #[Autowire('%app.webauthn.fleet_replacement_deadline%')]
        private string $replacementDeadline,
    ) {
    }

    public function __invoke(CompromisedAuthenticatorDetected $event): void
    {
        if ($event->credentialRecord->aaguid->toRfc4122() === $this->fleetModel
            && $this->clock->now() < new DateTimeImmutable($this->replacementDeadline)
        ) {
            $event->admit();
        }
    }
}
```

The two parameters hold the AAGUID of the admitted model and the date its authenticators are replaced. See [Admitting a compromised authenticator](../../pure-php/advanced-behaviours/attestation-and-metadata-statement.md#admitting-a-compromised-authenticator) for the content of the event.

## Enterprise attestation

!!! info

    **New in v5.4.0**

An enterprise attestation chains to a root certificate of the organization, which no Metadata Statement lists. Pin these trust anchors, as PEM or Base64-encoded DER certificates, under `metadata`:

```yaml title="config/packages/webauthn.yaml" linenums="1"
webauthn:
    metadata:
        enabled: true
        mds_repository: 'App\Repository\MyMetadataStatementRepository'
        status_report_repository: 'App\Repository\MyStatusReportRepository'
        enterprise_attestation_trust_anchors:
            - '%env(file:ORGANIZATION_ROOT_CA)%'
```

When the creation options ask for `enterprise`, a full attestation must then chain up to one of these anchors, whether its AAGUID has a Metadata Statement or not. The status reports of the AAGUID still apply.

An application serving several organizations pins the anchors of the organization a registration belongs to, for that verification only. The devices another organization manages are then refused:

```php linenums="1"
$result = $this->verifier
    ->forAttestation('example.com')
    ->withEnterpriseAttestationTrustAnchors($organization->attestationTrustAnchors)
    ->verify($request);
```

The serial number of the authenticator is available on the trust path of the credential record. See [Enterprise attestation](../../pure-php/advanced-behaviours/attestation-and-metadata-statement.md#enterprise-attestation) for the rules applied and for reading the serial number.
